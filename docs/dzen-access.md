# Проверка доступа к Дзену (issue #1)

Основа — локальная версия [Andrrreyiv/dzen-publish](https://github.com/Andrrreyiv/dzen-publish).
Проверка использует её подключение CDP и общую навигацию в канал; кнопку создания статьи не нажимает.
Успешный transport healthcheck ещё не подтверждает вход или права редактора.

## Windows Chrome → агент на Linux

В PowerShell из каталога этой версии проекта:

```powershell
powershell -NoProfile -File dzen-publish/ensure_cdp_chrome.ps1
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -R 127.0.0.1:19222:127.0.0.1:9222 <SSH-alias>
```

Первый вызов открывает видимый Chrome с отдельным профилем `C:\temp\chrome-cdp-profile`.
В этом окне войти в Дзен и открыть редактор нужного канала. Коды и пароль вводить только в браузере.
Второй вызов держать запущенным на время работы агента; `<SSH-alias>` — существующее подключение пользователя.
Настройки sshd должны разрешать remote forwarding и сохранять loopback-привязку (`GatewayPorts no`).
Проверить на сервере, что порт 19222 слушает только loopback. Не открывать CDP наружу.

В локальном `.env` на сервере:

```dotenv
DZEN_CDP_MODE=external
DZEN_CDP_URL=http://127.0.0.1:19222
DZEN_CHANNEL_URL=https://dzen.ru/profile/editor/<channel>
```

При недоступном внешнем CDP проверка не запускает серверный Chrome и не переходит на порт 9222.
`DZEN_CHROME_PROFILE` и `CHROME_BINARY` сервера в режиме external не используются.
В local-режиме Chrome запускается под пользователем рабочего стола; автоматическое отключение sandbox для root не поддерживается.
Переменные окружения приоритетнее `.env`. Для проверки в отдельном worktree путь конфигурации не переносить в Git.

## Запуск

Установить `requirements-publishing.txt`. Для реального CDP используется установленный Google Chrome; скачивать Playwright Chromium нужно только для изолированных браузерных тестов.

```bash
/root/.local/bin/codex-test-guard --timeout 10m -- .venv/bin/python tools/doctor.py --online --platform dzen --output .tmp/dzen-access/report.json
```

Проверка только Дзена не подключается к YouTube/Telegram и не требует зависимостей монтажа.
`doctor --online` без фильтра проверяет все три площадки. Обычный `doctor` выводит состояние локальных инструментов.
Весь Dzen worker ограничен 90 секундами, включая очистку; CDP подключается максимум дважды.
В конце закрываются только созданные проверкой вкладки и соединение Playwright, пользовательский Chrome остаётся открытым.

JSON содержит `status`, `reason`, `next`, `checked_at`, целевой `channel` и тип наблюдаемой страницы.
Код завершения 0 означает ready, 2 — blocked. Причины: configuration_error, cdp_unavailable,
browser_start_failed, login_required, insufficient_rights, wrong_channel, unknown_layout, timeout, cleanup_failed, internal_error.
Ошибка закрытия служебной вкладки или отключения драйвера возвращает blocked, даже если права были подтверждены.
После принудительного завершения зависшего worker служебная вкладка может остаться: проверить её вручную перед повтором.
При публичной странице без однозначных признаков входа выдаётся unknown_layout, а не утверждение об отсутствии прав.
Проверка специфичного элемента создания материала подтверждает доступ к интерфейсу редактора, но не успешность будущей публикации.
Неизвестную разметку сначала исследовать вручную; успешный локальный DOM-тест не подтверждает её актуальность.

Сохранять отчёты в `.tmp/`; не прикладывать профиль, cookies, `.env`, OAuth URL или снимки личных страниц к публичному issue/PR.
Тестовые команды выполняются последовательно через обязательный guard. Независимое ревью кода предшествует тестам;
PR создаётся после успешной живой проверки. Создание черновика и публикация — отдельные issues.
